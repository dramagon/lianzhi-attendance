# A任务：组织、员工、场所与审批

先读取AGENTS.md、docs/team/README.md、docs/team/contracts.md，核对最新main，保留现有登录、Session和权限。首轮分支：codex/member-a-organization。

## 第一小阶段：组织与公共接口

在R9000P跑通现有代码并确认MySQL环境。用V2迁移实现公司、部门、员工、办公场所与绑定，保留sys_user.id作为员工身份。

完成员工分页查询、新增、修改、停用和角色维护，处理关联数据的删除/失效行为。保护最后一个管理员，账号停用与角色调整对既有会话生效。演示资料与正式环境区分。

场所包含名称、公司、经纬度、坐标系、半径、启用状态；接地图选点与坐标采集，凭据由环境变量或本机配置提供，未配置明确说明。

先向B/C公布员工范围、场所查询与DTO；补齐共享写请求CSRF方法、业务错误响应、输入校验和公司数据范围判断。完成管理页面及员工资料页面。

## 第二小阶段：审批

用V4迁移完成请假、补卡、加班、本人申请列表、人事审批和历史。明确待审批、同意、拒绝、撤回及允许的状态转换。

员工只申请与查询自己的记录；审批者不能审批自己的申请，并受公司范围限制。处理重复审批、撤回后审批、时间冲突和错误参数。接B的考勤调整服务，以申请ID保证幂等，保留原始事件与调整来源；撤销已生效申请时明确反向调整规则。

同时完成员工申请页与人事审批页，向C公布审批查询和统计口径。

## 整合与交接

A协调公共文件、根路由/菜单、权限、README、迁移编号和合并顺序，仅接入能构建的模块。每个模块的缺陷由负责人修复，A操作最终合并与版本标记。

完成“建档→打卡→申请/审批→报表→AI”的共同联调，维护MySQL初始化和Windows完整启动说明。实际Windows和MySQL结果独立记录。

## 每阶段验收与GitHub同步

- 验证资料落库、引用关系、停用/权限行为；审批流和考勤调整可追溯。
- 拒绝越权与跨公司请求，保留已有登录/权限回归。
- 在docs/modules/a-api.md记录真实接口、字段、迁移、运行结果和给B/C的接入步骤。
- 后端运行mvnw.cmd test，前端运行npm run format和npm run build；认证/导航变化时运行npm run test:e2e。
- 小阶段完成即commit、push个人远端分支、创建/更新PR；核对远端SHA，报告验证与剩余事项。未成功push不能称为已上传。

先交付最小组织/员工/场所模型与共享约定，再完善审批；不要一次生成全部模块后才运行检查。
