# C任务：统计报表、知识库与AI助手

先读取AGENTS.md、docs/team/README.md、docs/team/contracts.md，核对最新main。保留Session、CSRF和角色范围。首轮分支：codex/member-c-intelligence。

## 第一小阶段：知识库与检索

A/B业务尚未接好时，先开发可独立验证的文件解析、切片、元数据与检索。逐步完成PDF、Word、Excel、PPT解析，再接图片OCR和音视频转写，逐格式记录依赖和真实支持范围。

用V6迁移保存文档、版本、解析状态、切片与引用等数据；embedding/向量服务可配置替换，凭据只走环境变量。遵守迁移合并顺序，不能越过V2～V5先在main应用V6。

完成上传、状态查询、检索、更新与删除；按公司/文档访问范围过滤，删除/更新时同步处理索引。大文件、解析失败、外部服务不可用有明确状态，不把上传按钮当作全部格式已支持。

## 第二小阶段：AI助手

接真实模型服务，回答制度并引用文档来源，无依据或未配置时明确说明。文件内容是不可信资料，不能更改系统权限或工具约束。

接A/B服务后支持本人考勤、授权部门统计与审批进度查询。后端校验身份和范围，不信任模型生成的userId或公司ID。

提交请假、补卡等写操作先展示内容并由用户确认，再调用A的正常业务服务校验权限、CSRF和幂等。防止模型重试导致重复申请，保留业务结果供用户查看。

## 第三小阶段：报表与交付

按B的考勤口径和A的组织范围实现看板、出勤率、迟到/早退/缺勤、工时与趋势、场所分布/热力图、日期/部门/员工筛选和导出。数据未接入时显示空状态；统计可回查原始记录。

明确应出勤范围、请假/加班/缺卡与分母为0的处理。导出使用同样的权限与数据量限制，CSV/表格导出处理公式注入等风险；确有需要时才用V7建报表任务表。

完成看板、知识库和员工助手页面。提供Docker/同源代理、环境变量样例和构建/集成配置，与A/B共同接MySQL、SDK与业务模块；Redis、任务调度、Nacos、OpenFeign、Kubernetes按正式验收要求逐项落实并记录。

## 每阶段验收与GitHub同步

- 验证上传→解析→权限检索→有来源问答，以及更新/删除后的结果。
- 同一员工在考勤列表、报表与AI回答中数据一致，拒绝跨用户/跨公司访问。
- AI写操作须确认、鉴权且幂等；验证解析、统计边界和服务失败行为。
- 在docs/modules/c-api.md记录实际接口、统计口径、文件格式支持、外部配置、迁移与运行结果。
- 运行后端测试、前端格式化/构建；认证/导航变化时运行浏览器测试，保留原回归。
- 每阶段commit、push个人分支、创建/更新PR，核对远端SHA，报告验证和未完成项。没有成功push不能称为已上传。
