# A 非强制场所的人脸打卡入口（2026-11-08）

用户已普通打卡成功，但找不到实际人脸识别。定位原因：打卡页原先只在全局/场所强制人脸时渲染验证面板；本机保留普通打卡策略，因此SDK和本人登记可用仍没有面板。

现新增明确的“本次打卡使用人脸识别”选项。SDK可用时显示，未登记则提示前往本人登记；勾选后按普通场所二维码、定位和方向准备本次验证，真实服务端返回有效凭据前不允许提交。检测/质量/活体/比对失败、凭据过期或切换令牌、方向、位置等情况不得沿用旧凭据；取消可选识别后恢复普通打卡，原服务端强制策略不能通过客户端取消。

服务端同时修复可选凭据此前可能被忽略的问题：创建新事件时，只要提供非null的faceVerificationId就按已有身份/挑战/版本规则消费。无效凭据拒绝并回滚；未提供凭据的非强制普通打卡保持兼容；已落库的同请求仍按原事件幂等返回。打卡成功时只有本次确实提交人脸凭据才附带人脸验证通过提示。原始考勤及既有资料不修改。

新增2项后端业务测试（明确测试SDK替身）：非强制凭据被消费且重试幂等；无效凭据拒绝并无打卡落库、无凭据普通打卡仍可用。新增浏览器用例覆盖可选识别失败阻止提交、通过后可提交、取消后不携带旧凭据、重新选择绑定当前请求；模拟接口拒绝实际打卡，不伪造业务成功。

前端format/build及同源整合包后端verify共362项通过（失败0、错误0、跳过0），包含本机显式启用的真实SDK初始化/无脸拒绝测试；新增业务测试使用测试专用SDK替身。独立临时H2环境完整浏览器49项通过，验证页面与契约，不声称该浏览器环境运行了真实人脸SDK。初次新增测试的泛型断言编译歧义已修正，最终完整构建通过。

已用更新后的完整整合包重启主站并实际浏览器复验：已登记且非强制人脸的账号能看到并勾选入口，随即出现“本次打卡人脸验证”区，缺二维码时给出明确准备提示且不能提交；取消选择后验证区关闭，原登记版本不变。此复验未采集真人、未提交打卡。原有数据库、密钥和SDK配置保留。

本轮不宣称新增了真人正/反样本识别、真实活体防攻击或完整人脸打卡现场验收证据，仍由用户实际操作确认。
