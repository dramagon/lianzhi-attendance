## 选择与范围

采用 PDFBox + Apache POI 的本地 Java 解析器：能精确保留不同格式来源，并复用昨天的 `knowledge.text`。通用 Tika 自动抽取虽然入口统一，但本次仍需定制来源与限制；调用外部解析服务需要新增配置/网络依赖，不适合作为今天的基础实现。

最低交付：PDF、DOCX、XLSX、PPTX 的真实正文解析；同时接入可使用合成文件验证的 XLS/PPT。旧 DOC、宏格式、图片 OCR、音视频转写不冒充已支持，单独记录状态。OCR/转写/embedding 仅定义可替换 Java 契约，不生成伪结果。

库版本基于官方页面和 Maven Central 核对：PDFBox 3.0.8、POI 6.0.0，后者要求 Java 17，符合项目目标。POM 增加解析依赖，属于本次 PR 明确列出的公共依赖变更，不改 Spring Boot/MyBatis/前端版本。

## 调用与来源

解析入口接收展示文件名和 byte[]，返回检测格式、明确结果码/中文提示、不可变的 TextSection 列表；失败不返回部分正文。不暴露库异常、服务器路径或文件内容。文件名不作磁盘路径，不信任扩展名：检查签名、OOXML 主部件及 OLE 类型。

来源映射：PDF 对应真实页码；Word 对应有序段落/表格位置，不伪造页码；Excel 对应工作表且保留行/列信息；PPT 对应幻灯片序号并提取文本框和表格。公式使用已缓存值或保留公式说明，不执行外部链接、公式或宏。

解析得到 TextSection 后直接交给现有 TextChunker，验证切片来源和码点偏移对应规范化正文。新服务不承担当日之外的上传、数据库、权限、检索或 AI 问答。

## 状态与限制

区分成功、无正文、空文件、不支持、格式不匹配、损坏、加密、输入/解析资源超限。扫描 PDF 无可提取文字为无正文/需要 OCR，不能算识别成功；混合 PDF 如有空白页，记录来源或提示而不虚构文本。

沿用 10MiB 输入限制；提取正文默认最多 2,000,000 码点、来源段最多 10,000，PDF 页数及表格单元格分别设置上限。OOXML 在加载前检查条目数、每条目解压量和总解压量，不关闭 POI 自身 ZIP 保护。文本输出在追加时检查限额，超限不返回半份内容。

当前是内部同步组件。文件大小、字符/条目限额不能保证任意恶意文档的 CPU/堆内存上限；正式开放上传前还需要隔离执行、超时和并发限制，不宣称已经完成这些能力。
