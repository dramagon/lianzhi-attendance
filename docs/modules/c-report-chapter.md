# C报告章节：统计、知识库与智能助手

## 设计目标与协作

C负责将A提供的身份、组织、场所和审批，与B的排班、考勤事件及日计算结果连接为可核查的报表与助手。项目采用Spring Boot模块化单体、Vue3、Session与CSRF；模块内使用Java服务调用，避免重复实现考勤算法。权限贯穿API、页面入口、文件下载、检索和模型调用。

## 数据与实现

统计通过B日记录形成授权范围的汇总、逐日趋势、场所分布和19列CSV；分母只计已结束且应出勤的人天，全天请假、休息、待结算分别展示，零分母显示无可计算结果。筛选支持日期、公司、部门、员工、场所；数据量超限要求缩小范围。小时分布使用B的有效签到/签退时间，跨夜按真实小时归类，含批准补卡，不能作为原始设备事件总数。

图表使用ECharts按需模块和SVG渲染。真实地图热力使用AMap插件，明确坐标转换和失败状态；未配置地图凭据时显示相对热度和数据表。工时预测为可解释基线：至少14个有效完成日，按时间顺序留出验证集，用MAE比较线性回归与历史均值，展示未来7日每应出勤人天有效分钟，仅作参考。

知识库使用V6新增表保存当前文档原件、切片、向量、状态和版本审计。Spring Task从数据库队列取任务；解析进程限时、限内存，上传后的排队/处理中断可恢复为明确失败并显式重试。文档替换先使旧切片失效，再重新索引；删除清除正文、向量和原件，保留审计元数据。文档所有权和公司范围来自服务端身份。

文本解析覆盖PDF、DOCX、Excel和PPT；图片/扫描PDF通过RapidOCR实际OCR，短音视频通过FFmpeg与faster-whisper实际转写。页码、表格/幻灯片和音频时间段被保留为引用定位。旧DOC、过大文件、无正文、未配置提供方和识别失败均明确显示，不能宣称支持所有文件。

向量使用真实Ollama embedding，可替换模型，限制维数与总存储预算，配置变化要求重建。当前有界精确余弦检索适用于小组项目规模。制度RAG先找有权阅读的文字依据，再将资料作为不可信数据交给模型；模型输出接受JSON Schema生成约束，随后继续校验来源ID、原文摘录、当前版本和权限。无依据、无效输出或来源已变化时不展示为有效回答。

员工业务查询直接读取A/B真实结果。自然语言申请建议仅生成可编辑草稿，A普通业务服务进行预校验；用户核对、预览并明确确认后，才使用会话绑定的确认标识和幂等请求编号提交。模型输出不能决定身份、公司、审批权限或代替确认。

## 验证与局限

自动验证覆盖业务口径、跨公司权限、上传与CSRF、版本竞争、删除后引用失效、外部服务失败、模型伪造引用与调用期间身份变化。Windows实际启动同源包，独立MySQL8验证迁移及数据库重启；真实本地模型、OCR、转写与向量验证和HTTP协议替身测试分别记录。详细结果见[最终验收记录](../verification/member-c-completion.md)。

部署提供Java同源整合包、Docker Compose/Nginx/MySQL、GitHub Actions和Kubernetes声明。Kubernetes声明不代表已部署集群；Redis、Nacos、OpenFeign、uni-app、云效及B真实SDK/手机现场链路仍需要整组按课程要求落实。C交付不能替代这些共同验收。

## 建议演示顺序

1. 双击根目录 `start-c-full.cmd`，等待打开本机页面，用合成账号登录。
2. 员工上传合成制度DOCX，观察排队到PARSED/READY，进行文字/向量检索并核对原文件。
3. 问制度问题，展开引用查看逐字原文；问无依据内容，观察明确无依据状态。
4. 更新制度，证明旧正文不再命中且旧引用404；删除后核对搜索及下载不可用。
5. 上传小型图片、扫描PDF及录音，展示识别结果和实际页码/时间段，说明自动识别可能出错。
6. 输入完整请假时间与原因生成建议，证明尚无申请记录；核对后预览、明确确认，再到A申请页查看唯一真实申请。
7. 用人事账号查看报表，筛选同一员工和日期，对照B日记录、审批来源与CSV；查看图表、小时分布、样本不足预测提示。
8. 关闭本次启动再重开，展示文档和申请仍在、旧会话需重新登录。地图真服务、SDK/手机、集群和云效缺配置时展示实际待验收项，不伪装成功。
