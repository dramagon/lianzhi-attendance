# 课堂展示包

目标是用最少环境准备，展示已经实现的考勤与审批链路。运行时只需要**Java 17或以上**，不需要Node、MySQL、Python或虹软SDK。前端、后端及依赖全部装在一个app.jar中，启动后不依赖外部服务。

## 直接运行

1. 完整解压`classroom-demo.zip`。Windows双击`start-demo.cmd`；Linux/macOS运行`sh start-demo.sh`。
2. Windows脚本启动成功后自动打开浏览器；也可访问`http://127.0.0.1:18080/login?redirect=/attendance/presentation`。
3. 点击登录页的“管理员”，再点“登录工作台”。公开演示密码为`Lianzhi@2026`，按钮会自动填入。
4. 保留启动窗口，点击“一键完整演示”，或按演示台1—5逐步操作。Windows窗口按回车、Linux终端按Ctrl+C停止本次服务。

自动模式会依次准备、上班、下班、提交请假、审批回写，每步结束稍作停顿便于讲解。“暂停自动演示”会等当前操作结束后停止，已经落库的记录保留；业务出错也会停下，不继续后面的步骤。进度标记依据后台核对到的记录，不按点击次数推断成功。

同一天在同一浏览器重开页面或重启同一个展示包后，可自动恢复，或点“恢复上次进度”。页面只在浏览器保存合成账号与请求/记录编号；恢复时重新登录合成员工并核对员工、场所、事件和审批，不保存Cookie、密码、二维码或照片，也不重新提交打卡/申请。换库、身份不匹配或已跨天时按提示重新准备，历史数据不会被删除。浏览器禁止长期存储时本页仍可演示，但关闭后不保证恢复。

如果没有Java，先安装OpenJDK17或以上并配置JAVA_HOME或PATH。本云端尝试获取官方Windows运行时被网络代理返回403，因此本包不含Windows JRE；不能声称尚未在现场执行的Windows启动已经验证。

## 建议展示顺序（约3分钟）

| 顺序 | 点击 | 实际展示内容 |
| --- | --- | --- |
| 1 | 准备演示数据 | 创建合成员工、场所、今天全天及明天9—18点排班，此时没有打卡记录 |
| 2 | 二维码识别并上班 | 管理员真实签发二维码，页面实际解码图片，切换合成员工提交，后端验签、校验、落库 |
| 3 | 二维码识别并下班 | 刷新签名二维码并重复识别，生成第二条事件；重复点击受服务端幂等/唯一约束保护 |
| 4 | 员工提交请假 | 合成员工提交明天9—18点的真实申请，当前仍为PENDING |
| 5 | 管理员同意申请 | 切换管理员，正常审批并回写B日结果，展示APPROVED、480分钟请假和来源申请ID |
| 6 | 规则试算 / 摄像头预览 | 展示迟到、缺卡、跨天规则；主动授权设备预览，SDK状态如实显示未接入 |

快速上下班可能为0分钟并带有迟到/早退，这是全天演示班次与实际服务端时间的计算结果。页面不硬编码正常出勤、工时或审批成功。点击“重新准备新一轮展示”会使用新的合成员工，不删除旧记录；刷新会重新查询数据库结果。

**定位明确使用固定演示坐标，不是实际GPS。** 二维码签发/图片解码和后台业务是真实执行；需要现场定位或摄像头扫码时，再进入原始打卡页及设备检查页使用实际设备。人脸识别/活体未接SDK，不作为展示通过项。

## 数据与隔离

- 仅监听本机127.0.0.1:18080，不能把该演示包公开部署或录入真实员工资料。
- 使用自己的`demo-data`数据库、头像和日志目录，不读取项目的`backend/data`或MySQL业务库。不要随意删除有价值的数据。
- classroom和demo必须同时显式启用，正常应用不会注册课堂状态接口或公开静态页面配置；所有API仍使用原有认证、CSRF和角色范围。
- 自动切换仅使用公开演示管理员及新建合成员工身份；没有服务端绕过权限、直接改表生成成功记录或模拟SDK恒真返回。
- 端口已占用时请关闭本次旧展示窗口再启动；脚本不会停止未知的已有进程。

## 从源码生成

先按项目说明构建后端与前端，再从仓库根目录运行：

```bash
python scripts/build-classroom-demo.py
```

输出在`artifacts/classroom-demo/`与`artifacts/classroom-demo.zip`。构建器拒绝明显过时的编译产物，保留Spring Boot嵌套JAR压缩格式。打包前先停止正在运行的展示包；压缩包只包含明确列出的程序、启动脚本、说明及版本清单，不包含demo-data、运行日志、Cookie或上传内容。

`manifest.json`记录源码提交和工作区是否有未提交更改。生成的二进制包和运行数据不提交Git；源码、构建器和测试随B分支交付。
